# AI Chat: saved conversations and image attachments

Date: 2026-11-03
Status: approved in conversation (design sections 1-4), extends `2026-11-03-ai-chat-design.md`

## Goal

Make `/chat` behave like claude.ai: conversations are saved on the server per user and reload after refresh, the page lists past chats, and messages can carry images that Claude can see.

## Decisions

- Conversations are private per user. No cross-user access, not even superadmin.
- Storage: one JSON file per conversation, `data/chats/<user>/<id>.json`, no database. `data/chats/` is git-ignored.
- Images: PNG, JPEG, WebP, GIF. At most 4 per message, 5 MB each. Type is decided from the file's first bytes. File names are generated by the server (16 hex chars + extension).
- Not included: markdown rendering, search across chats, sharing, cleanup of chats when a user is deleted.

## Data model

```
{ id, title, model, claudeSessionId, createdAt, updatedAt,
  messages: [{ role: 'user'|'assistant', text, images?: [name], t, error?: true }] }
```

- `id`: 24 hex chars. Username is sanitised with `[^A-Za-z0-9._-]` to `_`, the same rule as the sandbox folder.
- Title: first 60 characters of the first message, rename allowed (max 80).
- Limit 200 chats per user: creating one more removes the least recently updated.
- Writes are atomic (temp file then rename). Appends read the file, change it, and write it back in one synchronous step.
- Original images live in `data/chats/<user>/<id>/img/`. `claude-ro` must not be able to read `data/`.

## API (admin and superadmin only, owner only)

- `GET /api/chats` returns `[{id, title, model, updatedAt}]`, newest first.
- `GET /api/chats/<id>` returns the conversation. `PATCH /api/chats/<id>` with `{title}`. `DELETE /api/chats/<id>`.
- `GET /api/chats/<id>/img/<name>` serves an image with `X-Content-Type-Options: nosniff` and `Cache-Control: private`.
- `GET /api/chat/models` as before.
- `POST /api/chat` body `{message, chatId?, model?, images?: [dataUrlOrBase64]}`. No `chatId` creates a conversation. The first SSE event is `{chatId}`. The client no longer sends `sessionId`; the server keeps the Claude session id in the conversation file and resumes with it when it is a UUID.
- A `chatId` that is not 24 hex chars, does not exist, or belongs to another user gives 404. Bad images give 400.

## Chat flow

1. Validate message, model, images. Load or create the conversation.
2. Save images to the conversation's `img/` folder. Append the user message to the file before Claude runs, so it survives a crash.
3. Rebuild the user's sandbox, create `_uploads/` in it and copy only this message's images there (mode 0644, folder 0755). The text sent to Claude on stdin gets one line per image naming its `_uploads/<name>` path. Claude reads images with its `Read` tool. Earlier images are already part of the resumed Claude session.
4. Stream as before. On the Claude session id, store it. On finish, append the assistant message. On Claude error or timeout, append an assistant message with `error: true`. On client disconnect, append whatever text arrived.
5. A project folder named `_uploads` is skipped when building the sandbox.

## Front-end

- Two columns: chat list on the left (title, time, rename, delete with confirmation), conversation on the right. On narrow screens the list opens as a panel.
- Attach by button, paste (Ctrl+V) or drag-and-drop. Thumbnails with a remove button before sending. Sent images show in the message; click opens the full image in a new tab.
- The last conversation opens on load. The model dropdown value is saved per conversation.
- All text through `textContent`. Images through `<img src="/api/chats/...">`.

## Deployment notes

- nginx defaults reject large bodies (413) and cut streams after 30 s. A `location /api/chat` block with `client_max_body_size 30M`, `proxy_read_timeout 150s` and `proxy_buffering off` is added to both nginx example configs.
- POST body limit for `/api/chat` becomes 28 MB (4 images of 5 MB as base64, plus text). Other routes keep their limits.
- Prompt injection through image text is possible. Claude only has read tools, and the system prompt already treats file contents as data.
- `claude-ro` creation needs sudo, which `zae` lacks on the VPS, so `scripts/setup-claude-ro.sh` is provided for the owner to run. Nothing on the VPS is changed by this work.

## Tests

`node:test`: id validation including `../`, user isolation (read, delete, image), magic-byte check rejects a fake PNG, size and count limits, server-made file names, 200-chat cap, list order, user message kept when Claude fails, partial text kept on disconnect, and resume uses the stored session id.
